## 3.1 Kafka与对象存储接口边界说明

Kafka 与 Object Storage（S3）列入上表仅为协议全景完整性，二者均不属于本文档的REST/MQTT/WebSocket接口面：

- **Kafka**：为后端内部事件流，主题清单与事件Schema由03号功能设计文档的事件体系（17个核心事件）与10号部署文档的Kafka主题规划定义，不对外暴露为 /api/v1 REST接口。
- **对象存储（MinIO/S3）**：媒体文件（图片、视频、红外文件）的上传下载经后端签发的预签名URL（Presigned URL）访问，平台API面不直接代理文件流。

# 7. 统一状态码

| Code  | 含义        |
| ----- | --------- |
| 0     | 成功        |
| 40001 | 参数错误      |
| 40002 | 数据不存在     |
| 40003 | 状态非法      |
| 40101 | 未认证       |
| 40301 | 无权限       |
| 40401 | 资源不存在     |
| 40901 | 重复请求      |
| 40902 | 资源冲突      |
| 42901 | 请求过于频繁    |
| 50001 | 服务异常      |
| 50002 | AI服务异常    |
| 50003 | UAV通信异常   |
| 50004 | 第三方厂商接口异常 |

错误码语义界定（40002 与 40401 不删除任一编码，按以下规则区分使用）：

- **40401（资源不存在）**：对应REST资源路径不存在（HTTP 404语义），例如 /api/v1/missions/{id} 中该ID无对应资源。
- **40002（数据不存在）**：对应业务层引用的数据对象不存在，例如请求参数中引用的 fireIncidentId/mediaId 在库中无记录。

判定规则：先判定请求路径，再判定业务引用——路径指向的资源不存在返回40401；路径有效但请求所引用的业务对象（如fireIncidentId、mediaId）不存在返回40002。

# 31. 命令状态机

```

 ↓

 ↓

```

## 31.1 平台侧与设备侧命令状态映射（2026-09-28 补入，关闭 ISSUE-004）

平台侧 CommandStatus（本枚举，REST/DB 口径）与设备侧 DeviceCommandStatus（05号第42章，MQTT UAV_COMMAND_RESULT.status 口径）是两个层面。规范映射如下，由 **UAV Gateway 在上行回调时翻译**写入平台记录：

| 设备侧（UAV_COMMAND_RESULT.status） | 平台侧（uav_command.status） | 说明 |
| --- | --- | --- |
| （无，命令创建时） | CREATED | 平台创建、未下发 |
| （无，gateway 发布 MQTT 后） | SENT | 已送达 broker |
| RECEIVED | SENT | 设备已接收，平台仍为已发送（到达确认） |
| VALIDATING | SENT | 设备校验中 |
| ACCEPTED | ACKNOWLEDGED | 设备接受待执行 |
| EXECUTING | EXECUTING | 执行中 |
| SUCCESS | SUCCESS | 成功（终态） |
| FAILED | FAILED | 失败（终态） |
| TIMEOUT | TIMEOUT | 超时（终态） |
| REJECTED | FAILED | 设备拒绝执行，平台记 FAILED 并保留拒绝原因 |
| CANCELLED | INTERRUPTED | 设备取消/被打断（终态） |

反向约束：平台侧不得向设备直接下发 ACKNOWLEDGED/SUCCESS 等仅平台侧存在的状态；设备侧 REJECTED/CANCELLED 不得原字落入库（网关必须翻译）。

**MVP 实现偏差（如实记录，2026-09-28）**：当前 backend 的 `PATCH /api/v1/commands/{id}/status` 直接接受设备侧 9 值写入 `uav_command.status`（初始 CREATED/SENT 由平台写），**尚未实现上表翻译**。MVP 演示链路（GOTO 全流程）已实测兼容（设备回 RECEIVED→EXECUTING→SUCCESS 与平台期望顺序一致）。该翻译逻辑为演示后第一批工程化的清单项，本表即其验收标准。

# 33. API设计原则

1. 前端不得直接调用UAV厂商接口。
2. AI服务不得直接控制无人机。
3. AI返回的是算法结果，不是业务事件。
4. Backend负责业务状态机。
5. UAV Gateway负责设备通信。
6. Vendor Adapter负责厂商差异。
7. 所有关键链路必须可追踪。
