# 3. 环境划分

环境体系统一为四个：

```
DEV
DEMO
TEST
PROD

```

其中 DEV → TEST → PROD 为发布演进链路，DEMO 为独立演示环境，不承担发布流转。

### DEMO演示环境

定位：

- 仅用于项目演示、技术汇报、功能演示、客户演示；
- 禁止真实飞行；
- 禁止生产数据；
- 禁止正式业务。

架构（单机）：

```
Frontend
Backend
AI Service
UAV Gateway
Mock UAV
PostgreSQL
Redis
MQTT
MinIO

```

第一版DEMO不要求Kafka集群。

固定场景（至少6个）：

所有场景必须可重复执行，支持一键启动、一键复现。

```
Scenario-01 正常巡检
Scenario-02 火情发现
Scenario-03 二次核验
Scenario-04 误报
Scenario-05 火势扩大
Scenario-06 UAV断联

```

数据策略：

- DEMO使用独立数据库，与DEV/TEST/PROD完全隔离；
- 提供reset-demo重置，重新加载UAV/Fire/Mission/Telemetry/Media演示数据。

```

```

```
↓
```

```
↓

↓
```

```
↓

↓

```

# 73. 扩容原则

当出现：

```
CPU持续过高
Memory持续过高
AI Queue持续增长
Kafka Lag增长
数据库压力持续升高

```

再进行扩容。

扩容顺序：

```
无状态服务
→ AI Service
→ UAV Gateway
→ Kafka Consumer
→ Database

```

数据库扩展需要单独设计，不直接通过简单增加容器实例实现。

# 76. 生产故障优先级

### P0

系统整体不可用；

数据库严重故障；

无人机控制链路大面积异常；

核心安全机制失效。

### P1

AI服务不可用；

UAV Gateway大面积异常；

任务系统无法工作。

### P2

单个功能异常；

单台设备异常；

非核心接口异常。

### P3

界面问题；

统计问题；

非关键日志问题。

# 77. 运维核心原则

系统运维必须遵守：

```
先保护飞行安全
↓
再保护业务数据
↓
再恢复核心服务
↓
最后恢复非核心功能

```

涉及真实无人机时：

> 软件平台出现异常，不得以继续执行自动飞行为默认恢复策略。
