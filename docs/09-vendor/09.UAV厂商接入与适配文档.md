# 3. 为什么必须采用Adapter

不同厂商在以下方面可能不同：

```
设备身份
遥测字段
坐标系统
控制接口
任务格式
云台控制
相机
红外
航线
直播
媒体下载
通信方式

```

如果业务代码直接写：

```
if DJI
   ...
else if XXX
   ...

```

最终会变成：

```
业务代码
+
大量厂商判断

```

维护成本会急剧增加。

所以应该：

```
业务系统
↓
统一接口
↓
Adapter
↓
厂商SDK/API

```

# 4. 统一UAV能力接口

内部抽象：

```
interface UAVAdapter {

    DeviceInfo getDeviceInfo();

    UAVState getState();

    UAVCapability getCapability();

    CommandResult takeoff();

    CommandResult land();

    CommandResult gotoPoint(TargetPoint target);

    CommandResult gimbalLookAt(TargetPoint target);

    CommandResult captureRGB();

    CommandResult captureThermal();

    CommandResult returnHome();

    CommandResult pause();

    CommandResult resume();

    MissionResult executeMission(Mission mission);
}

```

以上为13方法冻结接口（00基线V1.3继承v1.0第23章冻结定义），Mock Adapter与所有厂商Adapter必须完整实现。

说明：executeMission 的任务执行结果经命令/事件通道异步回传，与命令状态机（CREATED→SENT→ACKNOWLEDGED→EXECUTING→SUCCESS/TIMEOUT/FAILED/INTERRUPTED）保持一致，不做同步阻塞语义。

V1核心命令集（九项）：

```
TAKEOFF
LAND
GOTO
GIMBAL_LOOK_AT
CAPTURE_RGB
CAPTURE_THERMAL
RETURN_HOME
PAUSE
RESUME

```

命令语义由05号（UAV统一协议）与本文档（09号）共同定义，机器来源 docs/00-doc/enums.yaml。

# 6. DJI接入架构

DJI当前官方Cloud API将DJI行业设备抽象成云端物模型，并以MQTT、HTTPS和WebSocket等协议进行云端通信。官方文档描述的架构中，飞机并不是直接连接第三方云平台，而是通过DJI Pilot 2、DJI Dock等网关侧组件间接连接。

因此系统设计：

```
DJI UAV
   ↓
DJI RC / DJI Dock / Pilot 2
   ↓
DJI Cloud API
   ↓
DJI Adapter
   ↓
UAV Unified Interface
   ↓
Forest Fire Platform

```

# 10. DJI状态映射

示例：

```
DJI Property
        ↓
DJI Parser
        ↓
UAVState

```

统一结果：

```
{
  "deviceId": "DJI-001",
  "latitude": 35.1234,
  "longitude": 139.1234,
  "absoluteAltitude": 120.5,
  "relativeAltitude": 100.0,
  "groundElevation": 20.5,
  "battery": 85,
  "heading": 180.5
}

```

高度字段映射（00基线V1.3第37-38章）：

```
DJI elevation = Relative takeoff point altitude
↓
relativeAltitude

DJI height = Absolute height（椭球）
↓
absoluteAltitude

```

统一内部高度三字段语义：

```
absoluteAltitude = 相对于参考椭球面的绝对高度
relativeAltitude = 相对于起飞点的高度
groundElevation  = 地面高程

```

该映射按具体DJI设备属性文档执行。

# 11. DJI航线任务

DJI Cloud API提供Wayline相关能力，用于发布、执行、取消和报告航线任务；官方文档还定义了WPML航线文件格式。

因此：

```
Forest Fire Mission
↓
Mission Planner
↓
DJI Wayline Generator
↓
WPML/KMZ
↓
DJI Adapter
↓
DJI设备

```

注：任务的业务类型 MissionType（PATROL/RISK_PATROL/FIRE_VERIFICATION/FIRE_TRACKING/THERMAL_INSPECTION/SUPPORT）由02号文档定义，本文档与厂商任务类型只做映射引用，不重新定义。F12 的 RECON/VERIFY/TRACK 属 Multi-UAV Task Role（RECON→PATROL或RISK_PATROL、VERIFY→FIRE_VERIFICATION、TRACK→FIRE_TRACKING），不是新 MissionType，不得进入 MissionType 枚举。

# 12. 路线规划与厂商航线格式解耦

系统内部：

```
Waypoint[]

```

例如：

```
[
  {
    "lat": 35.123,
    "lon": 139.123,
    "altitude": 120,
    "altitudeMode": "RELATIVE_TO_TAKEOFF"
  },
  {
    "lat": 35.124,
    "lon": 139.124,
    "altitude": 125,
    "altitudeMode": "RELATIVE_TO_TAKEOFF"
  }
]

```

高度参考系约束（00基线V1.3第39章）：TargetPoint 的 altitude 必须与 altitudeMode 同时出现，altitudeMode 至少支持：

```
ELLIPSOID
RELATIVE_TO_TAKEOFF
AGL

```

禁止使用无参考系的裸高度值。

然后：

```
Waypoint[]
↓
Vendor Adapter

```

DJI转换为其要求的航线文件/任务格式。

以后其他厂商可以：

```
Waypoint[]
↓
Other Adapter
↓
Other Mission Format

```

# 13. DJI云台目标指向

DJI Cloud API文档包含`camera_look_at`能力，用于令载荷朝向指定的经纬度和高度目标；具体可用能力必须按具体机型和载荷能力矩阵进行校验。

因此内部统一定义：

```
GIMBAL_LOOK_AT

```

而不是在业务代码中写：

```
DJI_CAMERA_LOOK_AT

```

统一定义：

THERMAL
ZOOM
WIDE
NIGHT

```

# 15. 厂商能力矩阵

每个接入设备必须建立：

| 能力                | 是否支持 |
| ----------------- | ---- |
| RGB               | Y/N  |
| Thermal           | Y/N  |
| Zoom              | Y/N  |
| Gimbal            | Y/N  |
| Gimbal Look-at    | Y/N  |
| Wayline           | Y/N  |
| Live Stream       | Y/N  |
| Media Upload      | Y/N  |
| RTK               | Y/N  |
| Remote Control    | Y/N  |
| Battery Telemetry | Y/N  |
| Extinguishing Ball Dropper（灭火弹投放器） | Y/N  |
| Loudspeaker（喊话器） | Y/N  |
| Supply Drop（应急物资仓） | Y/N  |

能力矩阵作为F09调度的能力匹配输入，是F09调度算法选择执行设备的重要依据。

> 注：`Extinguishing Ball Dropper`、`Loudspeaker` 与 `Supply Drop` 为 2026-10-05~06 demo 增补行（分别随 CommandType#DROP_EXTINGUISHING_BALL、#LOUDSPEAKER_BROADCAST 与 #DROP_SUPPLIES，见 change-log）。当前 mock-uav 均标注 Y（MOCK 模拟执行）；真实机型接入（Phase 9A）时按实际挂载重新标注，未挂载对应载荷的设备其投弹/喊话/投放物资入口均应视其为 N。

# 16. DJI接入不能直接照搬官方Demo

需要特别注意：

DJI官方GitHub上的Cloud API Demo已经在2025年4月10日宣布停止维护，并明确说明该Demo并非生产级解决方案，因此不能把它直接作为生产系统基础代码。应该以持续更新的官方Cloud API文档和当前设备能力说明为准。

所以：

```
官方文档
→ 理解协议
→ 自己实现Adapter

```

而不是：

```
复制官方Demo
→ 改改数据库
→ 直接上线

```

```

↓

↓

## Vendor Safety Profile

系统软件电量基线（00基线V1.3第36章）：

| 状态                  | 阈值   |
| ------------------- | ---- |
| LOW_BATTERY_WARNING | 30%  |
| NO_NEW_MISSION      | 25%  |
| RETURN_HOME         | 20%  |
| CRITICAL            | 10%  |

真实设备接入时，可按机型定义 Vendor Safety Profile 覆盖上述软件基线；覆盖值必须记录并审计，且不得低于飞控/电池自身的厂商失效保护。
