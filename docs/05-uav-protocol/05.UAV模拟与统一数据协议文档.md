# 1. 文档目的

本项目当前存在一个现实问题：

> 真实无人机型号、厂商以及最终接入方式尚未完全确定。

因此不能让算法和后端直接依赖：

```
DJI JSON

```

或者某一种特定无人机的数据格式。

本项目采用：

```
真实无人机 / DJI / 其他厂商
                ↓
          数据适配 Adapter
                ↓
       UAV Unified Data Model
                ↓
       算法 / 后端 / 数据库

```

开发初期则采用：

```
Mock UAV
   ↓
UAV Unified Data
   ↓
算法
   ↓
后端
   ↓
任务
   ↓
Mock UAV执行
   ↓
新数据

```

因此：

# UAV Unified Data 是整个系统的数据契约。

## 3.1 不复制厂商协议

```
“DJI标准”

```

而定义：

```
“平台 UAV 标准”

```

例如：

```
DJI
   ↓
DJI Adapter
   ↓
UAVUnifiedState

```

其他无人机：

```
Other UAV
   ↓
Other Adapter
   ↓
UAVUnifiedState

```

Mock：

```
Mock UAV
   ↓
Mock Adapter
   ↓
UAVUnifiedState

```

三者最终进入相同的数据处理链。

# 4. 与 DJI 数据的关系

DJI 当前 Cloud API 的公开数据模型已经包含很多与本项目直接相关的基础遥测，例如 GPS/RTK 数量、电池容量、剩余飞行时间、Home 点、姿态、相对/绝对高度、经纬度、水平/垂直速度等。([github.com](https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/60.api-reference/10.pilot-to-cloud/00.mqtt/10.m3-series/00.properties.md?utm_source=chatgpt.com))

DJI Cloud API 目前基于 MQTT、HTTPS、WebSocket 等协议提供第三方云平台接入能力。([developer.dji.com](https://developer.dji.com/cloud-api/?utm_source=chatgpt.com))

因此，本标准会参考这些通用字段，但：

> **UAV Unified Data ≠ DJI 原始数据。**

```

其中 UAV_TELEMETRY、UAV_CAPABILITY、UAV_ENVIRONMENT 三种消息此前仅有类型名，补充载荷定义如下。三条载荷只复用本文档第9~34章已定义的子模型字段，不新增任何字段名；其机器可执行 Schema 落于 docs/protocol/uav-json-schema/（基线第5章，后续步骤生成）。

## 8.1 UAV_TELEMETRY 载荷

UAV_TELEMETRY 是 1Hz 高频遥测消息（第85章，高并发场景可到 5Hz/10Hz/20Hz），经 uav/{deviceId}/telemetry Topic 上行（第47/49章）。载荷取第9章 UAV 状态统一模型中具有连续遥测语义的子模型子集，与 UAV_STATE（全量状态，第36章）形成"全量 / 高频轻量"两层。

选用了 position、attitude、velocity、battery、navigation、link 六个子模型，依据：

- 第4章将经纬度、绝对/相对高度、姿态、水平/垂直速度、GPS/RTK 数量、电池容量、剩余飞行时间列为与本项目直接相关的基础遥测；
- 第85章 TELEMETRY 为 1Hz 高频数据；
- 第33章明确"环境信息与无人机遥测必须分开"，environment 不进入本消息，由 UAV_ENVIRONMENT 单独上报；
- device 与 capability 为静态信息，gimbal/payload 属负载业务数据，flight/home 的任务级变化由 UAV_MISSION_STATE 与 UAV_EVENT 上报，均不属于高频遥测语义。

| 字段        | 类型   | 必填   | 说明                          |
| ----------- | ------ | ---- | ----------------------------- |
| position    | object | √    | 位置子模型，字段见第12/13章   |
| attitude    | object | √    | 姿态子模型，字段见第15/16章   |
| velocity    | object | √    | 速度子模型，字段见第17章      |
| battery     | object | √    | 电池子模型，字段见第19/20章   |
| navigation  | object | √    | 导航子模型，字段见第18章      |
| link        | object | √    | 链路子模型，字段见第31章      |

## 8.3 UAV_ENVIRONMENT 载荷

载荷即第33章 environment 环境模型字段，字段完全复用第33章定义。该消息落实第33章原则"环境信息与无人机遥测必须分开"：环境数据来自气象站/气象API（environment.source 标注来源），environment.windSpeed 是气象风速，与 UAV 自身估算风速（uav_estimated_wind）不是同一概念，两个字段绝对不要混。

| 字段          | 类型   | 必填   | 说明                                       |
| ------------- | ------ | ---- | ----------------------------------------- |
| temperature   | number | √    | 环境温度                                   |
| humidity      | number | √    | 环境湿度                                   |
| windSpeed     | number | √    | 气象风速（非 UAV 估计风，见第33章）        |
| windDirection | number | √    | 气象风向                                   |
| source        | string | √    | 环境数据来源，如 WEATHER_STATION（第33章） |

消息示例：

```
{
  "schemaVersion": "1.0",
  "messageId": "MSG-20260927-000401",
  "messageType": "UAV_ENVIRONMENT",
  "deviceId": "UAV-001",
  "timestamp": "2026-09-27T10:00:00Z",

    "temperature": 31.5,

# 14. 高度定义

为了避免不同厂商高度概念混乱，统一定义：

```
absoluteAltitude
=
相对于参考椭球面的绝对高度

relativeAltitude
=
相对于起飞点的高度

groundElevation
=
当前地面高程

```

DJI 当前文档区分 `height` 和 `elevation`，其中 `height` 是相对地球椭球面的高度，而 `elevation` 是相对起飞点高度；因此平台内部必须避免简单把所有“height”字段混为一个字段。([github.com](https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/60.api-reference/10.pilot-to-cloud/00.mqtt/10.m3-series/00.properties.md?utm_source=chatgpt.com))

统一 DJI 字段映射（基线第38章）：

```
DJI elevation（Relative takeoff point altitude）
→ relativeAltitude

DJI height（Absolute height，椭球高）
→ absoluteAltitude

```

# 19. Battery 电池模型

```
{
  "battery": {
    "percentage": 76,
    "voltage": 23500,
    "current": 4200,
    "temperature": 38.2,
    "remainingFlightTime": 920,
    "returnHomeThreshold": 20,
    "landingThreshold": 10
  }
}

```

按基线第36章，平台软件电量基线统一为四级：

| 状态                  | 阈值   |
| ------------------- | ---- |
| LOW_BATTERY_WARNING | 30%  |
| NO_NEW_MISSION      | 25%  |
| RETURN_HOME         | 20%  |
| CRITICAL            | 10%  |

其中 returnHomeThreshold 对应 RETURN_HOME（20%），landingThreshold 对应 CRITICAL（10%，触发紧急降落）。

真实设备可使用 Vendor Safety Profile 覆盖软件基线。

# 21. Battery 仿真规则

Mock UAV 不应让电量随机变化。

应该根据飞行状态计算。

例如：

```
悬停：

每分钟消耗 0.6%

普通飞行：

每分钟消耗 1.0%

高速飞行：

每分钟消耗 1.5%

负载较大：

每分钟额外 +0.3%

```

最终：

```
battery(t+1)
=
battery(t)
-
consumptionRate

```

特别注意：

**environment.windSpeed 与 UAV 自身估算风速不是同一概念。**

DJI 当前文档明确说明其 `wind_speed` 是基于飞行器姿态估计得到的参考值，存在误差，不能作为气象数据。([github.com](https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/60.api-reference/20.dock-to-cloud/00.mqtt/10.aircraft/10.m3d-properties.md?utm_source=chatgpt.com))

因此：

```
UAV估计风
    ↓
uav_estimated_wind

气象站/气象API
    ↓
environment.wind

```

两个字段绝对不要混。

# 40. 标准 Command Type

V1 核心命令集（基线第28章，原九项；2026-10-05 demo 增补第10项 DROP_EXTINGUISHING_BALL、第11项 LOUDSPEAKER_BROADCAST；2026-10-06 demo 增补第12项 DROP_SUPPLIES，见 change-log）：

```
TAKEOFF
LAND
GOTO
GIMBAL_LOOK_AT
CAPTURE_RGB
CAPTURE_THERMAL
RETURN_HOME
PAUSE
RESUME
DROP_EXTINGUISHING_BALL
LOUDSPEAKER_BROADCAST
DROP_SUPPLIES

```

**DROP_EXTINGUISHING_BALL（投放灭火弹，demo 增补项）**：

- 语义：向 payload 指定目标点投放一枚灭火弹（机载灭火剂弹，MOCK 实现）。
- payload 必须携带：`latitude`、`longitude`（目标点）、`incidentId`（关联火情事件）。
- 机载安全校验（不满足则命令 FAILED，附原因）：① 弹药余量 >0（挂载量 `constants.yaml#extinguishing_ball.capacity`，当前 3）；② 与目标点距离 ≤ `drop_max_radius_m`（当前 150m）。
- permission：`uav:command`（控制类行为，写入 AuditLog）。
- 真实投放器适配属 Phase 9A（09号第4章 Adapter 冻结接口届时扩展），当前仅 mock-uav 模拟执行。

**LOUDSPEAKER_BROADCAST（机载喊话警告，demo 增补项）**：

- 语义：通过机载喊话器（MOCK 实现）向地面播报森林防火警告，用于巡检发现可疑人员/非法用火/盗伐迹象时的现场警告与震慑。
- payload 可选：`message`（自定义播报词）；缺省播报机载默认词 `constants.yaml#loudspeaker_broadcast.default_message`（"严禁野外用火，保护森林安全。同时警告，任何盗伐、滥伐林木的行为都将受到法律严惩。"）。
- 执行：机载播报约 `duration_seconds`（当前 5s）后回 SUCCESS，`result.message` 回传实际播报全文供平台展示留档；无距离/弹药类前置校验（任意位置可喊话）。
- permission：`uav:command`（控制类行为，写入 AuditLog）。
- 真实喊话器/TTS 适配属 Phase 9A，当前仅 mock-uav 模拟执行。

**DROP_SUPPLIES（投放应急物资，demo 增补项）**：

- 语义：向无人机当前位置投放一份机载应急物资包（MOCK 实现），用于巡检发现受伤/受困人员或地面扑火队伍需要补给时的应急支援。
- payload：无必选字段（快捷指令一键投放，落点=无人机当前位置；`result.latitude/longitude` 回传实际投放点供平台留档，`result.item` 回传物资内容描述）。
- 机载安全校验（不满足则命令 FAILED，附原因）：① 物资余量 >0（挂载量 `constants.yaml#supply_drop.capacity`，当前 3）；② 无人机在空中（LANDED 状态拒绝空投）。
- permission：`uav:command`（控制类行为，写入 AuditLog）。
- 真实物资仓适配属 Phase 9A（09号第4章 Adapter 冻结接口届时扩展），当前仅 mock-uav 模拟执行。

CommandType 语义由 05 UAV统一协议 + 09 UAV适配 共同定义，机器来源：docs/00-doc/enums.yaml。

 ↓

 ↓

 ↓

 ↓
