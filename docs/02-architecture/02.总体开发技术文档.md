# 2. 项目总体定位

本项目不以“建设一个无人机管理平台”为核心目标。

真正的技术目标是：

> **研究并工程化森林防火场景下，无人机多源数据如何经过算法处理形成业务能力，再通过后端业务规则和任务决策将分析结果转化为无人机可执行任务，并将执行结果重新反馈给系统。**

核心链路：

```
无人机感知
    ↓
数据接入
    ↓
统一数据模型
    ↓
算法分析
    ↓
业务事件
    ↓
业务决策
    ↓
任务生成
    ↓
无人机执行
    ↓
数据反馈
    ↓
再次分析

```

因此项目核心可以概括为：

# 感知 → 分析 → 决策 → 执行 → 反馈

# 3. 项目建设依据

2026 年 1 月 28 日发布、2026 年 5 月 1 日实施的 **GB/T 47054—2026《森林草原防火 无人机巡查技术规范》**目前为现行标准，明确适用于多旋翼、固定翼、复合翼等无人机开展森林草原防火巡查，并覆盖日常巡查、火情巡查、巡查准备、实施、完成及异常情况处置等内容。

2026 年同期实施的 **GB/T 47059—2026《森林草原火灾成因和损失调查评估规程》**目前同样为现行标准，可作为灾后调查评估业务设计的参考。

在设备接入方面，DJI Cloud API 当前通过 MQTT、HTTPS、WebSocket 等通用协议提供第三方云平台接入，并将部分底层设备能力进行抽象，官方当前列出的支持产品包含 DJI Dock 3、Matrice 4D/4TD、Dock 2、Matrice 3D/3TD、Matrice 4E/4T、Matrice 300 RTK、Matrice 30 系列、Mavic 3 Enterprise 系列、Matrice 350 RTK 等；具体能力仍需按机型和载荷进一步验证。

# 19. Mission 任务体系

统一任务模型：

```
Mission
│
├── PATROL
├── RISK_PATROL
├── FIRE_VERIFICATION
├── FIRE_TRACKING
├── THERMAL_INSPECTION
└── SUPPORT

```

MissionType 所有权声明：

> MissionType 属业务任务语义，主定义文档为本文档（02 总体开发技术文档）；机器可读来源为 docs/00-doc/enums.yaml。03/07/08/09/11 等其他文档只能引用该枚举，不得另造同名不同值枚举。六项枚举值冻结：PATROL / RISK_PATROL / FIRE_VERIFICATION / FIRE_TRACKING / THERMAL_INSPECTION / SUPPORT。

F12 任务角色映射：

> F12 多机协同中的 RECON / VERIFY / TRACK 属于 Multi-UAV Task Role（多机任务角色），不是 MissionType。映射关系：RECON → PATROL（任务来源为普通巡检）或 RISK_PATROL（任务来源为风险区域）；VERIFY → FIRE_VERIFICATION；TRACK → FIRE_TRACKING。RECON / VERIFY / TRACK 不得进入 MissionType 枚举。

MissionType 与 CommandType 严格分离：

> MissionType 表示业务目的（如 FIRE_VERIFICATION），CommandType 表示无人机底层动作（如 GOTO / GIMBAL_LOOK_AT / CAPTURE_RGB / CAPTURE_THERMAL）。一个 FIRE_VERIFICATION 任务可包含上述命令；二者不得混用。

任务拥有：

```
Mission
├── UAV
├── Waypoints
├── Priority
├── Status
├── Target
├── Command
└── Result

```

# 66. 最终项目定义

本项目最终定义为：

> **面向森林防火场景，建设一套以无人机多源感知数据为基础，以 AI、GIS、风险分析、时序跟踪、预测和智能调度为核心的森林防火智能业务系统。系统通过统一的 UAV 数据标准屏蔽不同厂商设备差异，将原始无人机数据转化为火情发现、火点定位、二次核验、火场分析、火势跟踪、风险评估、巡检规划、无人机调度、多机协同和灾后评估等业务能力，并通过任务和指令机制将业务决策重新传递给无人机执行，最终形成“感知—分析—决策—执行—反馈”的闭环。**
