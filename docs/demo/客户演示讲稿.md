# 客户演示讲稿（5 分钟版）

> 配套系统：森林防火无人机智能感知与闭环决策系统
> 核心叙事：**感知 → 分析 → 决策 → 执行 → 反馈**，全程在一张地图上讲完
> 建议时长：5 分钟正式演示 + 5 分钟自由操作

------

## 一、演示前检查清单（提前 30 分钟）

- [ ] Docker Desktop 已启动，`docker compose ps`（在 deploy/ 下）显示 **9 个容器全部 Up**，其中 postgres/redis/minio 为 healthy
- [ ] 浏览器打开 http://localhost:8181 ，能看到地图与巡航中的无人机标记
- [ ] 执行过 `bash scripts/reset-demo.sh`（干净底座：无历史事件、无人机满电）
- [ ] 网络确认：地图瓦片为本地离线 Esri 卫星瓦片（898 块随前端发布），**断网可正常演示**；联网时远程 Esri 源自动垫底扩大覆盖。避免把地图拖出瓦片覆盖区边缘
- [ ] 分辨率设 1080p、浏览器缩放 100%，右上角应显示"后端已连接"绿色角标
- [ ] 口径确认：界面标注"算法模拟模式"，讲稿按第二节话术处理 AI 部分

## 二、演示剧本（按顺序，每步含操作与话术）

### 开场（30 秒）

> "这是我们的森林防火无人机智能系统。它不是一个看无人机的平台，而是一条**从发现到处置的完整闭环**：感知、分析、决策、执行、反馈。下面 5 分钟走一遍真实链路。"

### 1️⃣ 感知层：正常巡检（30 秒）

**操作**：点击【▶ Scenario-01 正常巡检】
**画面**：无人机沿航线巡航，右侧面板电量、速度、GPS/RTK 实时刷新
**话术**：

> "无人机每秒回传位置、姿态、电量、链路等全量状态，数据实时入库——这是闭环的感知层，也是后面一切分析的输入。"

### 2️⃣ 自动发现：注入火情（60 秒）

**操作**：点击【🔥 Scenario-02 火情发现】
**画面**：无人机加速转场（15m/s）→ 到达可疑点悬停采集 → **地图弹出橙色脉冲火点**，右侧事件列表出现"疑似火情"
**话术**：

> "我们模拟无人机在巡检中发现可疑烟雾。注意——**不需要任何人盯屏幕**：图像回传后算法自动检测、自动定位火点、自动生成火情事件。这个过程刚刚发生了，事件编号在列表里。"

### 3️⃣ 分析层：AI 二次核验（45 秒）

**操作**：点开事件卡，点击【触发核验】
**画面**：核验结论 **CONFIRMED，置信度 0.904**，事件变红色
**话术**：

> "检测只是第一道。二次核验综合可见光、热红外、时序、空间四类证据加权判定——**这一步把误报挡在出动之前**。误报演示稍后专门给您看。"

### 4️⃣ 决策支撑：火场分析（60 秒）

**操作**：连点两次【🔥 火场分析】
**画面**：地图出现**两圈扩散的火场多边形**（年轮效果），下方趋势面板显示"扩散中、方向、速度、面积增长率"
**话术**：

> "确认火情后，系统持续提取火场范围、计算蔓延方向和速度——指挥员据此判断该往哪个方向布防，而不是靠经验猜。"

### 5️⃣ 决策与执行：自动派单核验（60 秒）

**操作**：事件卡点击【派单核验】
**画面**：系统自动选中无人机、生成任务、下发 GOTO——地图上无人机**自动飞向火点**，指令状态从执行中变为成功
**话术**：

> "这是闭环的关键一跳：系统自动调度最近的可用无人机，自动生成核验任务、自动下发飞行指令。调度依据——距离、电量、能力、链路——全部留档可解释。"

### 6️⃣ 反馈与排除：误报演示（45 秒）

**操作**：点击【⚠️ Scenario-04 误报】→ 新事件出现后【触发核验】
**画面**：第二个事件，检测置信度不低，但核验结论 **FALSE_ALARM（自动排除）**，事件变灰
**话术**：

> "同样的管线，换一个场景：视觉上可疑、但多证据核验不通过，系统**自动排除误报、避免无效出动**。发现火情靠算法，排除误报也靠算法。"

### 收尾（30 秒）

> "从发现到确认到处置反馈，全程数据入库、全程可追溯。当前演示用的是算法模拟模式保证效果稳定；真实检测模型、真实无人机接入（大疆 Cloud API）已在架构内预留，是下一阶段的直接工作项。"

## 三、自由操作环节备答

- 客户想自己点：给他们 GOTO 点地图 + 快捷起飞/返航；误报/火情场景可重复注入
- 被问"数据存在哪"：PostgreSQL + PostGIS 空间数据库，34 张表，全链路可追溯
- 被问"支持什么无人机"：架构已抽象适配层，已支持大疆 Cloud API 与 MAVLink 两大协议族，具体机型接入是配置工作
- 被问"误报率"：给出核验目标——确认精度 ≥0.90、误报率 ≤0.10（基线冻结的 V1 验收目标）

## 三·五、随时取消：Scenario-01 是“解药”

**任何场景进行中，点顶栏【▶ Scenario-01 正常巡检】= 取消当前场景**：停止采集、恢复普通巡航、事件列表保留为历史。用途：场景演砸了重来、无人机不在预期位置、或者临时被客户打断。讲剧本时如果 02/04 的事件不是你想要的那个，点 01 清场再重新注入即可。

## 四、风险与应对

| 风险 | 征兆 | 应对 |
| --- | --- | --- |
| 现场断网 | 边缘放大偶发无瓦片 | 已内置 898 块离线卫星瓦片，演示区不依赖外网；把地图拖回覆盖区内即可 |
| 容器异常 | 角标"后端连接断开" | `cd deploy && docker compose up -d` 重拉；必要时 `docker compose restart backend` |
| 数据被玩乱 | 事件列表混乱 | `bash scripts/reset-demo.sh` 一键重置（10 秒） |
| 无人机"不动了" | 电量 <25% | mock 模拟器低电保护；重启 mock-uav 恢复满电：`docker restart forest-fire-mock-uav` |
| AI 判定波动 | 模拟模式置信度小幅随机 | 属正常设计（0.86~0.97 抖动），结论判定阈值不变 |

## 五、演示后

- `bash scripts/reset-demo.sh` 恢复干净状态
- 如客户要留存：事件数据都在库中，可导出（psql COPY 或后续导出接口）
