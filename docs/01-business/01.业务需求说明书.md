# 1. 文档说明

## 1.1 文档目的

本业务需求说明书用于明确森林防火无人机智能系统到底要解决什么业务问题，以及系统必须具备哪些业务能力。

本项目不以开发一个“无人机管理平台”为最终目标。

项目的核心目标是：

> **利用无人机获取的可见光、热红外、位置、姿态及其他环境数据，通过算法分析形成森林防火业务信息，再通过业务规则和任务机制形成巡查、核验、跟踪、调度等行动，实现从“发现问题”到“执行处置”的业务闭环。**

因此，平台只是承载这些能力的工具。

------

# 2. 项目背景

森林草原火灾具有突发性强、影响范围广和现场处置困难等特点。2026 年发布并于 **2026 年 5 月 1 日实施**的 GB/T 47054—2026《森林草原防火 无人机巡查技术规范》，明确适用于多旋翼、固定翼和复合翼等无人机开展森林草原防火巡查，并覆盖**日常巡查、火情巡查、巡查准备、巡查实施、巡查完成以及异常情况处置**等内容。国家市场监督管理总局的标准解读材料还明确指出，无人机已经成为森林草原防火巡查的重要技术手段。

2026 年同时实施的 GB/T 47059—2026《森林草原火灾成因和损失调查评估规程》，为火灾成因调查和损失评估提供了现行国家标准依据，可以作为本项目灾后评估业务设计的参考。

因此，本项目业务体系应覆盖：

```
灾前预防
    ↓
日常巡查
    ↓
异常发现
    ↓
火情核查
    ↓
火情确认
    ↓
动态监测
    ↓
辅助决策
    ↓
任务调度
    ↓
灾后评估

```

# 4. 总体业务目标

项目需要实现以下六个总体目标。

## 4.1 从人工发现向智能发现转变

通过无人机影像、热红外等数据，辅助发现：

- 烟雾
- 火焰
- 异常热源
- 可疑燃烧区域
- 其他火险异常

------

## 4.2 从“发现火”向“确认火”转变

避免系统发现一个疑似异常就直接当成火灾。

形成：

```
疑似
 ↓
二次核验
 ↓
确认

```

------

## 4.3 从“一个火点”向“完整火情”转变

火灾事件应具备：

```
位置
时间
面积
范围
变化趋势
影像证据
无人机轨迹
核验结果
处置任务

```

------

## 4.4 从被动巡查向主动巡查转变

根据：

- 历史火情
- 天气
- 植被
- 地形
- 人类活动
- 风险区域

确定重点巡查区域。

------

## 4.5 从单架无人机向任务调度转变

当多架无人机可用时，系统应根据：

- 距离
- 电量
- 当前任务
- 载荷能力
- 通信状态
- 预计到达时间

辅助选择执行任务的无人机。

------

## 4.6 从“给人看”向“闭环执行”转变

最终形成：

```
发现
 ↓
判断
 ↓
派任务
 ↓
无人机执行
 ↓
返回数据
 ↓
再次判断

```

13. 火势趋势辅助预测
14. 灾后过火区域评估
15. 数据和业务过程留痕

------

## 5.2 不属于一期重点范围

以下能力暂不作为一期核心业务：

- 完全无人值守自主灭火
- 自动替代人工消防决策
- 大尺度火灾物理仿真
- 全国尺度火灾预测
- 复杂经济损失核算
- 完整三维数字孪生
- 全自动飞行许可管理

这些属于后续扩展能力。

# 11. F01 火灾早期发现

## 11.1 业务需求

系统应能够利用无人机可见光影像或视频，自动辅助识别森林区域中的：

- 烟雾
- 火焰
- 可疑燃烧目标

------

## 11.2 业务场景

```
无人机正常巡检
 ↓
实时采集
 ↓
系统发现烟雾
 ↓
生成疑似火情
 ↓
通知相关人员

```

------

## 11.3 业务输入

包括：

- RGB 图片
- 视频帧
- 拍摄时间
- 无人机位置
- 飞行高度
- 设备编号

------

## 11.4 业务输出

系统生成：

```
异常类型
置信度
发现位置
发现时间
图片证据
关联无人机

```

------

## 11.5 业务规则

单次模型识别结果不一定直接产生正式火情。

推荐：

```
单帧检测
+
连续帧确认
+
空间信息

```

形成疑似火情。

------

## 11.6 业务结果

```
NORMAL
或者
SUSPECTED_FIRE

```

------

# 12. F02 红外异常热源检测

## 12.1 业务需求

系统应支持利用热红外数据识别森林区域内异常热源。

------

## 12.2 业务价值

解决：

```
可见光无法明显看到
但是热源已经异常

```

的情况。

------

## 12.3 业务输入

- 热红外影像
- 温度信息
- 拍摄位置
- 时间
- 无人机信息

------

## 12.4 业务输出

- 最大温度
- 平均温度
- 异常区域
- 异常位置
- 异常置信度

------

## 12.5 业务规则

不能：

```
异常高温 = 确认火灾

```

而应：

```
热异常
+
RGB结果
+
时间连续性
+
空间环境

```

进入火情核验。

------

# 13. F03 火点精确定位

## 13.1 业务需求

系统应能够将 AI 从影像中识别的火/烟目标转化为地图上的具体地理位置。

------

## 13.2 输入

- 检测框/像素坐标
- UAV 经纬度
- 高度
- UAV 姿态
- 云台姿态
- 相机参数
- 必要时的地形数据

------

## 13.3 输出

```
火点坐标
定位误差
定位置信度

```

------

## 13.4 业务意义

只有完成火点定位，后续才能：

```
创建核验任务
调度无人机
跟踪火势
计算距离
生成地图事件

```

------

# 14. F04 火情二次核验

## 14.1 业务需求

系统对疑似火情进行二次验证。

核心业务流程：

```
疑似火情
 ↓
选择可用无人机
 ↓
飞往目标
 ↓
重新取景
 ↓
RGB + 红外
 ↓
再次分析
 ↓
确认/误报

```

------

## 14.2 业务结果

三种：

```
CONFIRMED
FALSE_ALARM
UNCERTAIN

```

------

## 14.3 业务规则

只有满足预设置信条件或人工确认条件，才将：

```
SUSPECTED

```

升级为：

```
CONFIRMED

```

------

火场中心
火场变化

------

## 16.2 关注指标

```
火场面积
火点位置
扩散方向
扩散速度
变化趋势

```

------

## 16.3 业务结果

例如：

```
稳定
扩大
快速扩大
方向改变
减弱

```

------

## 16.4 业务触发

如果：

```

+

# 17. F07 森林火险风险评估

## 17.1 业务需求

## 17.2 输入因素

### 历史

- 历史火情
- 历史火灾频率

### 环境

- 温度
- 湿度
- 风
- 植被
- 地形
- 坡度

### 人类活动

- 道路
- 景区
- 建筑
- 施工区域
- 人员活动

------

## 17.3 输出

```
LOW
MEDIUM
HIGH
CRITICAL

```

并生成：

```
风险区域
风险分数
风险原因

```

生成任务

```

------

## 18.3 业务输出

```
巡查区域
任务优先级
航线
无人机
预计时长

```

# 19. F09 无人机智能调度

## 19.1 业务需求

当发生事件，需要选择无人机执行任务时，系统应提供智能调度结果。

------

## 19.2 主要判断因素

```
距离
电量
剩余飞行时间
当前任务
红外能力
变焦能力
通信状态
预计到达时间

```

------

## 19.3 业务结果

例如：

```

FIRE_VERIFICATION

UAV-001

UAV-003

UAV-002

```

# 20. F10 灾后过火区域评估

## 20.1 业务需求

火情结束后，通过灾前/灾后影像比较，形成灾后影响区域数据。

------

## 20.2 输入

- 灾前影像
- 灾后影像
- 火灾区域
- 森林空间数据

------

## 20.3 输出

```
过火面积
过火区域
植被影响区域
道路影响
设施影响

```

GB/T 47059—2026 已于 2026 年 5 月 1 日实施，其中业务方向即为森林草原火灾成因和损失调查评估，因此该模块可作为后续业务扩展的重要依据。

# 21. F11 火势趋势预测

## 21.1 业务需求

基于当前火势和环境因素，辅助判断短时间内火情可能发展的方向和范围。

------

## 21.2 输入

```
当前火场
历史火场变化
风向
风速
温度
湿度
地形
坡度
植被

```

------

## 21.3 输出

```
10分钟预测
30分钟预测
60分钟预测

```

结果应该明确标记：

```
预测结果
+
置信度

```

不能把模型预测当作确定事实。

# 22. F12 多无人机协同

## 22.1 业务需求

在复杂火情中，支持不同无人机承担不同任务。

例如：

```
UAV-001
发现

UAV-002
红外核验

UAV-003
持续跟踪

```

------

## 22.2 业务目标

从：

```
一架无人机执行全部任务

```

# 28. 业务规则：检测去重

多架无人机可能同时发现一个火情。

系统需要根据：

```

```

进行事件聚合，避免一个真实火情生成多个重复事件。

形成：

多个火场边界

# 64. 本项目业务需求最终定义

本项目的核心业务需求可以浓缩为：

> **利用无人机作为森林防火的移动感知与执行终端，对森林区域进行日常巡查和重点巡查；利用可见光、热红外、定位和遥测等数据，通过 AI 识别、空间定位、火场分割、时序跟踪、风险分析和趋势预测等能力，将原始数据转化为疑似火情、确认火情、火场范围、火势趋势和风险区域等业务结果；再通过任务生成和无人机调度，将业务结果转化为实际巡查、核验、跟踪和协同任务；任务执行后的新数据再次进入系统分析，形成“感知—识别—核验—分析—决策—执行—反馈”的森林防火业务闭环。**

# 65. 本文档与研发的关系

业务需求确定以后，研发按照以下顺序展开：

```
业务需求
    ↓
12个功能详细技术设计
    ↓
UAV统一数据协议
    ↓
数据库设计
    ↓
算法实现
    ↓
后端实现
    ↓
Mock UAV
    ↓
业务闭环测试
    ↓
真实无人机接入
    ↓
平台承载

```

最终验收不是看：

> 页面做得多漂亮。

而是看：

> **12 个业务能力有没有真正形成可执行、可验证、可追溯的业务闭环。**
