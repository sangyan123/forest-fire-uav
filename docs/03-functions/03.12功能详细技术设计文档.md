# 3. 行业和技术依据

目前中国已发布 **GB/T 47054—2026《森林草原防火 无人机巡查技术规范》**，该标准于 2026 年 1 月 28 日发布、2026 年 5 月 1 日实施，目前状态为现行标准。该标准本身就是本项目设计日常巡查、火情巡查和无人机作业流程的重要业务依据。

同时，DJI Cloud API 当前采用 MQTT、HTTPS、WebSocket 等通用协议，并将底层无人机硬件能力抽象出来，支持第三方云平台接入。官方公开的数据模型中已经包含当前位置、高度、速度、姿态、Home 点、GPS/RTK、风速估计、电池等数据；同时提供 `camera_look_at` 这类面向目标经纬度和高度的云台/负载控制能力。

需要特别注意：DJI 文档中的 `wind_speed` 是依据飞行器姿态估计得到的风速，官方明确说明有误差，**不能作为气象数据使用**。因此火势预测功能必须优先使用独立气象数据源，DJI 风速只能作为辅助信息。

近期 UAV 森林火灾研究已经涉及 RGB/热红外融合、火灾检测、火场分割以及 RGB/热红外与风场、地形、植被融合的近时火势预测，因此下面的功能划分既有工程落地基础，也保留了研究型功能空间。

# 9. F01——森林火灾早期发现

## 9.1 功能目标

通过无人机 RGB 图像和视频，在火灾早期识别：

- 烟雾
- 明火
- 可疑燃烧区域

核心是：

> 从“有人看视频”升级为“系统自动发现异常”。

------

## 9.2 输入数据

### 必需字段

```
imageUrl
timestamp
uavId
latitude
longitude
altitude
cameraType

```

### 可选字段

```
gimbalPitch
gimbalYaw
zoom
flightDirection
weather

```

------

## 9.3 算法流程

```
RGB/视频帧
    ↓
图像预处理
    ↓
目标检测模型
    ↓
烟雾/火焰检测
    ↓

    ↓

    ↓

    ↓

```

------

## 9.4 算法方案

一期：

- YOLO
- RT-DETR
- 轻量 YOLO

二期：

- 小目标检测
- 多尺度特征增强
- 时序一致性
- RGB-Thermal 融合

UAV 森林火灾检测研究已经证明 RGB 和热红外可以在复杂背景、遮挡和昼夜场景下形成互补；2025–2026 年的研究仍在继续针对轻量化和多模态融合优化。

------

## 9.5 算法输出

```
{
  "detectionId": "DET-001",
  "type": "SMOKE",
  "confidence": 0.94,
  "bbox": [120, 160, 330, 410],
  "timestamp": "2026-09-27T10:00:00Z",
  "uavId": "UAV-001"
}

```

------

## 9.6 后端处理

```
Detection
 ↓
Confidence Filter
 ↓
Temporal Confirmation
 ↓
Fire Rule Engine
 ↓
Suspected Fire

```

推荐规则：

```
单帧置信度 > T1
AND
连续 N 帧出现
AND
目标位置相对稳定
AND
位于森林/风险区域

```

阈值参数取值（V1 工程基线，00基线 V1.3 第33章冻结）：

```
T_candidate        = 0.40    # 候选阈值（对应上式 T1，进入时序确认）
T_alert            = 0.60    # 告警阈值
T_confirm          = 0.80    # 确认阈值
TEMPORAL_WINDOW    = 5       # 时序确认窗口（帧）
MIN_POSITIVE_FRAMES = 3      # 5 帧窗口内至少 3 帧一致目标（对应上式"连续 N 帧出现"）

```

# 12. F04——火情二次核验

## 12.1 功能目标

降低误报。

逻辑：

```
AI发现疑似火情
        ↓
平台自动生成验证任务
        ↓
无人机接近目标
        ↓
RGB+IR二次采集
        ↓
再次识别
        ↓
确认 / 误报 / 不确定

```

------

## 12.2 输入

```
firstDetection
thermalResult
RGBResult
firePoint
timestampSequence
uavState

```

------

## 12.3 算法

建议：

```
RGB Detector
+
Thermal Detector
+
Temporal Evidence
+
Spatial Evidence

```

计算：

```
FinalScore =
w1 * RGBScore
+
w2 * ThermalScore
+
w3 * TemporalScore
+
w4 * SpatialScore

```

权重取值（V1 工程基线，00基线 V1.3 第34章冻结）：

```
w1 = 0.35（RGB）
w2 = 0.35（Thermal）
w3 = 0.15（Temporal）
w4 = 0.15（Spatial）

```

即：

```
VerificationScore = 0.35 * RGB + 0.35 * Thermal + 0.15 * Temporal + 0.15 * Spatial

```

决策阈值：

```
Score >= 0.80          → CONFIRMED
Score < 0.50           → FALSE_ALARM
0.50 <= Score < 0.80   → UNCERTAIN

```

------

## 12.4 输出

```
CONFIRMED
FALSE_ALARM
UNCERTAIN

```

## 91.2 页面定位与信息架构

页面名「火情风险检测」，回答三个递进问题：**哪里容易着火（F07）→ 火正往哪去（F11）→ 该派机去哪巡（F08）**；核心动作是生成巡检建议并一键下发成 RISK_PATROL 任务，与「森林防火」页处置链路衔接。布局沿用森林防火页「地图 + 右侧信息面板」骨架：

```
┌──────────────────────────────────────────┬────────────────┐
│ ① 风险地图（独立 Leaflet 实例）             │ ② 风险区域列表   │

│ ③ 顶部状态条：气象摘要 + 火情态势徽标（可开关） │ ④ 建议任务面板   │

└──────────────────────────────────────────┴────────────────┘
```

页面三态：**常态**（无活跃火情，纯 F07/F08）；**火情态**（存在 ACTIVE FireIncident，预测图层默认开启）；**已下发态**（建议 DISPATCHED 后展示关联 mission，点击跳森林防火页）。

## 91.5 一期算法与 mock 边界

- **F07 一期**：五因子加权评分（historical 0.30/weather 0.25/vegetation 0.20/terrain 0.15/human_activity 0.10），因子分值 0~100；因子数值由 ai-service mock provider 基于网格坐标确定性生成（同一格同值，可复现演示），气象取 mock；等级映射 ≥70 HIGH / ≥40 MEDIUM / <40 LOW。
- **F11 一期（Level 1 规则）**：以最新 fire_polygon 质心为火心，沿风向的椭圆扩散模型，参数见 constants.yaml fire_prediction.spread_model；置信度固定 0.78（Level 1 基准）。
- **F08 一期**：区域排序（risk_score 降序取前 5）+ 网格内蛇形覆盖航点（lane_spacing 80m、航高 100m、估时 9m/s），过滤既有点位约束后输出 waypoints。
